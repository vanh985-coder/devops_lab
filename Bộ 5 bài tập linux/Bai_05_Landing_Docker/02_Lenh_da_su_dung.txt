BÀI 5 - TRIỂN KHAI LANDING PAGE THƯƠNG MẠI BẰNG AI VÀ DOCKER
Danh sách lệnh quan trọng đã sử dụng
Sinh viên: Trần Đức Việt Anh | Server: maychucuavietanh (Ubuntu 24.04.1 LTS)
Thư mục dự án: ~/bai5/landing-page | Không chứa mật khẩu, key hay file VPN.
Các lệnh chạy trong phiên root (xem Sự cố S5 trong báo cáo).

======================================================================
A. ĐÓNG GÓI IMAGE (MC-01)
======================================================================
cd ~/bai5/landing-page
docker build -t devops-landing:v1.0 .
# -t <tên:tag>: đặt tên và tag cho image; dấu "." là build context (thư mục hiện tại).
# Dockerfile dùng FROM busybox:stable, WORKDIR /www, COPY index.html, EXPOSE 8080,
# CMD httpd -f -p 8080 -h /www (xem 03_Cau_hinh/Dockerfile_suy_ra.txt).

docker images                          # kiểm tra tên, tag, dung lượng image
docker history devops-landing:v1.0     # kiểm tra từng layer và image nền

======================================================================
B. TẠO NETWORK VÀ CHẠY CONTAINER
======================================================================
docker network create landing-net      # network riêng để gán IP cố định cho container
docker run -d -p 8080:8080 --restart unless-stopped \
  --name landing-public --network landing-net devops-landing:v1.0
docker run -d -p 8081:8080 --restart unless-stopped \
  --name landing-preview --network landing-net --ip 172.20.0.10 devops-landing:v1.0
# -d                    chạy nền
# -p <host>:<container> publish cổng; cả hai container nghe 8080 BÊN TRONG,
#                       ra host thành 8080 (public) và 8081 (preview)
# --restart unless-stopped  tự khởi động lại trừ khi bị dừng thủ công
# --network / --ip      gán IP cố định để rule firewall trỏ đúng container
# (Lệnh mục B là dựng lại theo trạng thái quan sát được ở MC-02, MC-03, MC-13.)

docker ps                              # trạng thái, cổng, tên container
docker port landing-public             # ánh xạ cổng thực tế
docker port landing-preview
ss -tuln                               # xác nhận cổng đã mở trên host

======================================================================
C. PHÂN TÁCH TRUY CẬP PUBLIC / PREVIEW BẰNG FIREWALL (MC-03)
======================================================================
ufw route allow proto tcp from any to 172.20.0.2 port 8080 \
  comment 'allow landing-public 8080/tcp landing-net'
ufw route allow proto tcp from 37.19.205.163 to 172.20.0.10 port 8080
ufw status numbered
# Phải dùng "ufw route" (ALLOW FWD) chứ không phải "ufw allow": gói tin tới
# container đi qua chain FORWARD sau khi Docker DNAT, không qua INPUT.
# Vì vậy "ufw allow 8081" sẽ KHÔNG chặn được truy cập tới container.

======================================================================
D. KIỂM THỬ TRUY CẬP TỪ CÁC NGUỒN MẠNG (MC-06 .. MC-10)
======================================================================
curl ifconfig.me                       # xác định IP công cộng của máy đang kiểm thử
curl http://103.216.118.115:8080       # bản public
curl http://103.216.118.115:8081       # bản preview
# Thực hiện lần lượt từ: Internet công cộng (113.23.44.41),
# VPN cá nhân (37.19.205.163), và một nguồn ngoài whitelist (172.216.245.25).

======================================================================
E. NÂNG CẤP v1.0 -> v1.1 (MC-11, MC-12)
======================================================================
nano index.html                        # đổi "DevOpsMaster" thành "DevOpsMaster-V1"
docker build -t devops-landing:v1.1 .
docker ps
docker stop landing-public
docker rm landing-public
docker run -d -p 8080:8080 --restart unless-stopped \
  --name landing-public --network landing-net devops-landing:v1.1
# Image v1.0 vẫn được giữ lại, nên rollback chỉ cần chạy lại container với tag v1.0.

======================================================================
F. KIỂM THỬ TỰ KHỞI ĐỘNG LẠI (MC-13)
======================================================================
systemctl restart docker
docker ps
# STATUS "Up 8 seconds" trong khi CREATED là 6-13 phút => container được khởi
# động lại chứ không phải tạo mới, chứng minh restart policy hoạt động.

======================================================================
G. LỆNH CẦN BỔ SUNG (chưa có minh chứng - xem mục 7.3 báo cáo)
======================================================================
docker logs --tail 50 landing-public            # log ứng dụng
du -sh /var/lib/docker/containers/*/*-json.log  # dung lượng log
docker inspect landing-public                   # cấu hình, IP, restart policy
docker stats --no-stream                        # mức dùng CPU/RAM thực tế
docker update --memory 128m --cpus 0.5 landing-public   # giới hạn tài nguyên
docker stop landing-public ; docker ps -a       # kịch bản chẩn đoán khi dừng
docker save -o devops-landing_v1.0.tar devops-landing:v1.0   # sao lưu image
reboot                                          # kiểm thử sau khi khởi động lại server
