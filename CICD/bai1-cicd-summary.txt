BÀI 1 - DỰNG LUỒNG CI/CD CƠ BẢN CHO APP DOCKER
Họ tên: Trần Đức Việt Anh

1. Repo tên gì
- Tên repo: san_thuong_mai_devops_course
- Link: https://github.com/vanh985-coder/san_thuong_mai_devops_course
- Nội dung: app web Java Spring Boot (FASTSHOP, thư mục FASTSHOP/net) chạy bằng Docker Compose
  trên server, gồm: app, SQL Server (db), db-init (tạo dữ liệu ban đầu), Prometheus, Grafana,
  node-exporter, cAdvisor.
- App đã chạy sẵn trên server trước khi làm bài, em chỉ bổ sung luồng CI/CD.

2. Workflow làm gì
Em chia thành 2 workflow:

* ci.yml ("Java CI") - kiểm tra code
  - Chạy khi push hoặc mở pull request vào nhánh dev, main.
  - Dev đẩy code lên GitHub -> GitHub Actions lấy source code về máy ảo Ubuntu
    -> cài Java 17 (có cache Maven) -> chạy ./mvnw clean verify để build và chạy test.

* cd.yml ("Java CD") - triển khai
  - Chỉ chạy khi Java CI chạy XONG và THÀNH CÔNG trên nhánh main (workflow_run).
    Nếu test fail thì không deploy.
  - Checkout đúng commit vừa test -> build Docker image -> push image lên GHCR
    (tag bằng commit SHA) -> SSH vào server bằng key -> pull image mới về
    -> chạy lại service app bằng docker compose -> kiểm tra container và curl app.

- Secrets đã tạo: SSH_HOST, SSH_USER, SSH_PRIVATE_KEY (private key không nằm trong repo).
- Public key nằm trong ~/.ssh/authorized_keys trên server.
- Server đã docker login ghcr.io bằng token quyền read:packages để pull được image private.

3. Pipeline chạy các bước nào
  Bước 1: Dev push commit lên main.
  Bước 2: Java CI: checkout -> setup Java 17 -> mvnw clean verify (build + test).
  Bước 3: CI xanh -> Java CD khởi động.
  Bước 4: Build image từ FASTSHOP/net/Dockerfile, push lên ghcr.io/vanh985-coder/san_thuong_mai_devops_course:<SHA của commit>.
  Bước 5: SSH vào server bằng SSH key, cd vào thư mục FASTSHOP/net, git pull --ff-only origin main
          (cập nhật docker-compose.yml và file cấu hình), ghi IMAGE_NAME và IMAGE_TAG vào .env.
  Bước 6: docker compose pull app -> docker compose up -d --no-deps app
          (chỉ khởi động lại app, không đụng database) -> docker image prune -f.
  Bước 7: docker compose ps, rồi curl http://localhost:18096/ (thử lại nhiều lần vì Java khởi động chậm).
          Nếu app không trả lời thì lệnh lỗi, pipeline đỏ (có set -e).

4. Deploy thành công hay chưa
- Thành công, đăng nhập server bằng SSH key.
  Commit 11f5f05: Java CI #17 xanh (53s), sau đó Java CD #11 tự chạy và xanh (1m34s).
  Ảnh: minh_chung/MC-05_ci_cd_xanh_bang_ssh_key.png
- Cách tạo key (ảnh MC-02, MC-03, MC-04):
  + ssh-keygen -t ed25519 -f ~/.ssh/fastshop_deploy -N "" -C "github-actions-fastshop"
  + Public key đưa vào /root/.ssh/authorized_keys, private key đưa vào Secret SSH_PRIVATE_KEY.
  + sshd -T xác nhận pubkeyauthentication yes, permitrootlogin yes.
- Các lỗi đã gặp trước khi thành công:
  + CI fail vì chưa có database: test Spring context cần kết nối SQL Server nhưng runner không có.
    Sửa: thêm SQL Server làm service container trong ci.yml.
  + CD fail vì nhầm giữa key và password khi cấu hình đăng nhập SSH trong workflow.
    Sửa: tạo key ed25519 riêng cho GitHub Actions, dùng đúng tham số key với Secret SSH_PRIVATE_KEY.
  + CD fail vì trên server không có file .env, lệnh sed sửa .env bị lỗi.
    Sửa: thêm touch .env trước khi ghi IMAGE_NAME, IMAGE_TAG.

6. Em rút ra được gì
- CI và CD là 2 việc khác nhau: CI kiểm tra code, CD đưa bản đã kiểm tra lên server.
  CD phải chạy sau CI xanh, nếu không sẽ deploy cả bản test fail.
- Build image trên GitHub Actions rồi đẩy lên registry thì server không tốn tài nguyên build,
  và tag theo commit SHA giúp biết đang chạy bản nào, rollback bằng cách chạy lại tag cũ.
  Thực tế doanh nghiệp thường làm theo cách này.
- GHCR mặc định private nên server phải đăng nhập mới pull được.
- Biến export trong phiên SSH sẽ mất, nên phải ghi vào .env để chạy docker compose bằng tay sau này.
- Pipeline xanh chưa chắc app chạy được, nên phải có bước health check ở cuối.
- Lỗi thường không nằm ở code mà ở môi trường: runner thiếu database, server thiếu file .env,
  cấu hình nhầm cách đăng nhập SSH. Phải đọc log từng bước trên tab Actions để biết lỗi ở đâu.

Ảnh đính kèm: repo, file ci.yml và cd.yml, trang Secrets, log Java CI và Java CD xanh,
docker compose ps, docker compose logs, curl.
